# Private Google Play account provisioning

Use a dedicated test Google account, not a personal account. Configure a dedicated trusted persistent Android host, preferably attached to a private repository; do not allow untrusted pull request jobs to run on that host. The existing branch workflow targets the hitel-private-android self-hosted runner and environment. Do not register a credential-bearing runner for arbitrary public jobs.

Set environment secrets GOOGLE_TEST_EMAIL and GOOGLE_TEST_PASSWORD in the protected hitel-private-android environment (repository secrets with the same names are supported by GitHub resolution but environment-scoped is preferred). Set HITEL_AVD_ROOT to a private persistent host directory. Neither credential is passed to Gemini or ARTEMIS, stored in code, logged, or uploaded. Run provision, then login; check existing session before entering credentials. The workflow must be available for workflow_dispatch and a trusted runner provisioned before it can execute. On MFA, CAPTCHA, consent, unfamiliar screen, or sign-in refusal, stop and complete the official Google UI manually. Do not disable account security. Subsequent boots reuse private AVD userdata; no credential-bearing snapshots or account logs are exported. Third-party Google sign-in can reuse the on-device account only where the target app offers it, with required user consent and app-specific authentication respected.

The login helper is a prototype and requires a real private-device test. No login is performed by this commit.

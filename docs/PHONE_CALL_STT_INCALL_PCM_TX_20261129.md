# Manual In-call PCM TX experimental module

Baseline: 7fb7c68e2c526773d65782baf9e90aa0906fc8d9 (best real telephone STT). The live RX/STT implementation is unchanged.
Select a completed Samsung 48 kHz AAC M4A, decode in advance to local mono PCM16LE; no TTS or external service. Send only when existing folder STT monitor is active, phone OFFHOOK and AudioManager MODE_IN_CALL. OFFHOOK includes dialing/hold; this is not a verified Telecom ACTIVE state. The helper also requires MODE_IN_CALL and confirmed TYPE_TELEPHONY routing before sending non-silent samples. It never mutes microphone, answers, hangs up or changes audio mode.
Reference: https://github.com/jemcik/JemRec/blob/main/shellserver/src/com/jemcik/jemrec/shell/GreetingPlayer.java (Apache-2.0; 48 kHz mono, USAGE_MEDIA, TYPE_TELEPHONY, MODE_STREAM; developer reports Galaxy S23 VoLTE success). ActivityThread shell setup pattern based on scrcpy/JemRec Workarounds. No source file copied verbatim.
Normal APK is not granted MODIFY_PHONE_STATE. Embedded libadb-android 3.1.1 uses the phone's own user-authorized Wireless debugging, with initial six-digit pairing and persisted app-private identity, then starts the shell helper from the installed APK via an authenticated local session. No PC, no legacy TCP debugging listener, no automatic settings grants. The phone may need Wireless debugging enabled again after restart; helper launch, identity, and Fold4 route require device testing. The helper's own socket is loopback-only with mutual HMAC authentication. Local playback head completion does not prove remote reception. Wi-Fi calling path not supported in this first TX test. Sample data remains private.
